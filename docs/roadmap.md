# 로드맵

**M0(골격)까지 끝났습니다. M1부터가 실제 작업입니다.**

> M1 은 새로 설계하는 단계가 아닙니다. **이미 써둔 테스트 34개를 켜는 작업**입니다.
> 함수 시그니처와 계약은 docstring 에, 기대 동작은 테스트에 있습니다.
각 마일스톤은 독립적으로 착수 가능하고, 끝날 때 눈에 보이는 결과물이 남습니다.

---

## M1 — 예약 도메인 로직

음성도 LLM도 없이, 예약 규칙만 먼저 못 박습니다. 여기가 틀리면 위에서 뭘 해도 소용없습니다.

- 슬롯 생성 잡 (근무표 + 휴진 → `slots`)
- `find_slots` — 진료과·의사·기간 조회
- `book_appointment` — 멱등, 충돌 시 실패 사유 반환
- 취소 시 슬롯 재개방

**테스트가 본체입니다.** 이미 빨간불로 올라가 있습니다.

| 파일 | 대기 중 | 내용 |
|---|---|---|
| `tests/test_slots.py` | 11 | 슬롯 경계, 점심시간 공백, 꼬리 버림, 휴진 부분 겹침, 시간대 |
| `tests/test_scheduling.py` | 17 | 후보 3개 제한, 멱등키 재사용, 충돌, 취소 후 재개방, 변경 원자성 |
| `tests/test_patients.py` | 6 | 번호+생년월일 식별, 전부 취소된 환자는 초진, 번호 공유 가족 |

동시 예약 충돌은 애플리케이션 락이 아니라 `appointments_active_slot` 유니크 인덱스로
판정합니다. 그 테스트만 실제 Postgres 가 필요해서 `@pytest.mark.db` 로 분리해뒀습니다.

미결 사항은 추측으로 메우지 않고 [open-questions.md](open-questions.md) 에 적어뒀습니다.
초진 진료시간(1번)은 M1 에서 정합니다.

## M2 — 텍스트 채널 에이전트

음성 빼고 대화 루프부터 세웁니다.

- 툴 4종 정의 및 LLM 연결
- 초진/재진 분기
- 범위 밖 질문 → `escalate_to_human`
- 3회 실패 시 에스컬레이션
- 시나리오 테스트 (해피패스 / 없는 시간 요청 / 말 바꾸기 / 증상 상담 시도)

끝나면 **텍스트로 예약이 잡힙니다.**

## M3 — 음성 연결

- LiveKit Agents 붙이기, 웹 위젯에서 통화
- STT·TTS 어댑터 인터페이스 + 벤더 1종 구현
- 한국어 STT·TTS 벤더 실측 비교 (정확도·지연·비용)
- 고유명사 커스텀 어휘 (의원명·진료과·의사명)

끝나면 **말로 예약이 잡힙니다.**

## M4 — 지연 최적화

이 프로젝트의 핵심 기술 과제. 목표는 발화 종료 → 첫 음성 출력 **800ms 이하**.

- 구간별 지연 계측 (`call_events`에 기록)
- STT 부분 결과로 LLM 선제 호출
- TTS 스트리밍
- 짧은 선응답 삽입
- 끼어들기(barge-in) 처리
- 턴 감지 튜닝

## M5 — 전화 인입

- SIP 트렁크 → LiveKit SIP Gateway
- 발신번호로 환자 선식별
- 통화 품질·끊김 처리

## M6 — 관리자 화면

- 예약 목록·변경·취소
- 통화 로그와 전사 열람
- 지연 지표 대시보드
- 단순 세션 인증

## M7 — 배포·관측

- Fly.io 배포
- 구조화 로그, 지연·실패율 알림
- 부하 상황에서의 동시 통화 처리
