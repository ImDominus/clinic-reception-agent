# 미결 사항

설계 단계에서 답을 못 정한 것들입니다. 추측으로 메우지 않고 적어둡니다.
각 항목은 어느 마일스톤에서 결정하는지까지 적습니다.

---

## 1. 초진 진료시간이 재진보다 길면 어떻게 표현할까 — M1

지금 `appointments` 는 `slot_id` 를 **하나만** 참조합니다. 초진이 30분이고
재진이 15분이라면 이 스키마로는 표현이 안 됩니다.

후보:

1. **연속 슬롯 묶음** — `appointment_slots` 조인 테이블. 유연하지만 "살아있는 예약은
   슬롯당 하나" 유니크 인덱스를 다시 설계해야 합니다. 지금 동시성 방어의 핵심이라 쉽게 못 건드립니다.
2. **초진 전용 근무 구간** — `provider_schedules` 에 초진 전용 줄을 둡니다. 스키마가 안 바뀌지만
   의사가 시간표를 두 벌 관리해야 합니다.
3. **초진은 슬롯 2칸 점유** — 예약 1건이 슬롯 2개를 막습니다. 1번의 축소판.

실제 의원 운영 방식을 모른 채 고르면 틀립니다. 당장은 **단일 슬롯 길이**로 가고,
`tests/test_slots.py::test_a_first_visit_needs_a_longer_appointment` 를 skip 으로 남겨둡니다.

## 2. 한국어 STT / TTS 벤더 — M3 전까지 실측

`docs/architecture.md` 는 후보만 적어뒀습니다. 재볼 것:

- **고유명사 인식률** — 의원명, 의사 이름, 진료과. 커스텀 어휘 사전을 받는 벤더인지.
- **첫 바이트 지연** — TTS 는 합성 전체 시간이 아니라 첫 소리가 언제 나오는지가 체감입니다.
- **부분 결과 품질** — 끼어들기 판정에 쓸 수 있을 만큼 부분 전사가 쓸만한지.
- **숫자 읽기** — "열한시 사십오분" 과 "11시 45분" 이 양방향으로 안정적인지.

벤더 이름을 코드에 박지 않습니다. `app/vendors/base.py` 프로토콜 뒤에 둡니다.

## 3. 취소로 열린 슬롯을 통화 중 다른 사람이 가져가는 경우 — M2

A 가 취소하는 동안 B 가 같은 시각을 찾고 있으면, B 에게는 방금 열린 자리가 보입니다.
B 가 "그 시간으로 하겠다"고 말하고 확정 버튼을 누르는 사이 A 가 취소를 철회하면?

지금 설계는 `book()` 이 유니크 제약으로 지는 쪽을 거절합니다. 기능적으로는 맞는데,
**전화 중에** "방금 없어졌습니다"를 듣는 경험이 나쁩니다. 후보 제시 후 짧은 소프트 홀드
(예: 90초)를 둘지 결정해야 합니다. 홀드를 두면 만료 처리가 또 상태 머신입니다.

## 4. 발신번호를 본인 확인으로 믿을 수 있나 — M5

SIP 로 들어오면 발신번호는 변조될 수 있습니다. 지금 설계는 발신번호를 **힌트로만** 쓰고
`lookup_patient` 가 전화번호 + 생년월일을 다시 받습니다. 이게 과한지 부족한지는
실제 의원 기준(접수 데스크에서 뭘 확인하는지)에 맞춰야 합니다.

## 5. 한 번호를 가족이 공유할 때의 통화 흐름 — M2

`(clinic_id, phone, birth_date)` 유니크로 사람은 구분됩니다. 문제는 대화입니다.
엄마가 아이 예약을 걸면 생년월일을 누구 걸로 받아야 하는지 모델이 헷갈립니다.
"누구 예약이세요"를 먼저 물을지, 생년월일을 받고 역추적할지. 프롬프트가 아니라
**흐름** 문제라 M2 에서 대화 시나리오로 정합니다.

## 6. 녹음은 안 남기는데 전사는 남긴다 — 경계가 맞나 — M7

README 의 데이터 원칙은 "통화 녹음 미보관, 텍스트 전사만"입니다. 그런데
`call_events.text` 에는 환자가 말한 내용이 그대로 들어갑니다. 증상을 말하면
그것도 들어갑니다 — 범위 밖이라 거절하더라도 **거절 전에 이미 전사됩니다.**

보관 기간, 범위 밖 발화의 마스킹, 전사 자체를 끌 수 있는 스위치 중 무엇을 둘지
정해야 합니다. 합성 데이터만 쓰는 데모라 급하지는 않지만, 실제로 쓸 거면 여기가 먼저입니다.
